01 Antes de empezar

Cuatro datos y estás listo. Los tres primeros te los da el administrador del marketplace.

DatoQué es
URL base El host del marketplace. Todas las rutas cuelgan de /api/v1.
API key Formato dw_…. Identifica a tu app. Solo se muestra una vez: guárdala en una variable de entorno.
meter El código de la tarifa que se te asigna, p. ej. consumo-apps. Define el precio por unidad.
location_id La subcuenta de GoHighLevel a la que cobras. Ya la tienes en tu propio OAuth.

La cabecera va en todas las llamadas. Las dos formas son equivalentes:

cabeceras
Authorization: Bearer dw_tu_api_key
# o bien
X-Api-Key: dw_tu_api_key
Bearer va con B mayúscula y un espacio. El servidor compara el prefijo literal: un bearer en minúscula cae al fallback de X-Api-Key y responde 401.

Sin cabecera o con una clave revocada recibes 401. Comprueba qué tarifas tienes disponibles y a qué subcuentas puedes cobrar:

bash
curl -H "Authorization: Bearer $MD_API_KEY" \
  https://marketplace.escaladoacelerado.es/api/v1/meters

# → {"meters":[{"code":"consumo-apps","unit_label":"unidad",
#      "price_type":"dynamic","default_price":0.01,
#      "min_price":0.01,"max_price":100}, …]}

02 Cobrar

Un único endpoint hace el trabajo. El resto de la API es para consultar.

POST /api/v1/charges
{
  "location_id": "sljtYiFoE1qS7x1sSAQW",
  "meter":       "consumo-apps",
  "units":       3,
  "event_id":    "hermes-conv842-lote7",
  "price":       0.05,
  "description": "3 mensajes de IA"
}
CampoReglas exactas
location_idobligatorio La subcuenta debe estar conectada y en estado connected.
meterobligatorio Código de la tarifa o meterId de GHL. Debe estar activa.
unitsobligatorio Número > 0 y ≤ 1 000 000, con un máximo de 4 decimales: la columna es numeric(12,4) y lo que pase de ahí se redondea en silencio.
event_idobligatorio Máx. 190 caracteres. Tu identificador único de la operación: es la clave de toda la idempotencia. Es único por (app, event_id), así que otra app puede usar el mismo valor sin colisionar contigo.
priceopcional Precio por unidad. Solo en tarifas dynamic, dentro de su mínimo y máximo (inclusive). En una tarifa fija devuelve 400; en una dinámica sin precio por defecto, es obligatorio.
descriptionopcional Máx. 500 caracteres. Por defecto, el nombre de la tarifa.
user_idopcional Texto libre, se guarda en el ledger.
event_timeopcional Fecha ISO 8601 válida.

El importe es units × price_per_unit, redondeado a 6 decimales. La divisa es siempre USD: GoHighLevel no admite otra.

El objeto charge que recibes

respuesta
{
  "id": 12,
  "event_id": "hermes-conv842-lote7",
  "location_id": "sljtYiFoE1qS7x1sSAQW",
  "meter": "consumo-apps",
  "units": 3,
  "price_per_unit": 0.05,
  "amount": 0.15,
  "currency": "USD",
  "status": "created",
  "paid_with": "wallet",   // o "credit"
  "kind": "usage",
  "ghl_charge_id": "abc123",
  "description": "3 mensajes de IA",
  "error": null,
  "created_at": "2026-09-06T12:30:01.000Z"
}

paid_with te dice si el importe salió del saldo interno del cliente o de su wallet de GHL. A tu app le da igual: en ambos casos está cobrado. Si se pagó con crédito, ghl_charge_id viene a null — eso no es un fallo.

Guarda el id numérico: es lo único que acepta DELETE /api/v1/charges/:id, no se puede reembolsar por event_id. Lee las respuestas por nombre de campo y tolera que aparezcan campos nuevos.

statusSignifica
createdCobrado. Sirve tu servicio.
testModo prueba: registrado, sin tocar dinero.
pendingEn vuelo hacia GoHighLevel.
failedGHL lo rechazó. Es reintentable con el mismo event_id.
unknownSin confirmación. Se reconcilia solo; nunca lo des por fallido.
refunded · refundingReembolsado o en curso de reembolso.

03 Qué hacer con cada respuesta

Esta tabla es el contrato. Si la implementas bien, no hay forma de cobrar dos veces al cliente.

■ sigue adelante ■ reintenta con el mismo event_id ■ arregla la petición
CódigoCuerpoQué haces
201 { test_mode, charge } Cobrado. Sirve el servicio.
200 { idempotent: true, charge } Ese event_id ya estaba cobrado. No es un error: sigue adelante y no vuelvas a cobrar.
200 { reconciled: true, … } Un intento anterior sí llegó a cobrar en GHL y se ha recuperado. Sigue adelante.
409 { error, charge_id } Ese event_id tiene un cobro en curso. Espera 2–5 s y repite la misma petición.
429 { error } Superaste el límite por minuto. Backoff y repite.
502 { error, charge } GHL rechazó el cobro (failed) o no lo confirmó (unknown). Repite con el mismo event_id: la pasarela comprueba en GHL si el intento anterior cobró antes de volver a ejecutarlo.
503 { error, charge_id } No se pudo verificar el intento anterior contra GHL. Repite en unos segundos.
400 { error } Campo ausente o inválido. Reintentar igual no sirve: corrige la petición.
401 { error } Falta la API key o está revocada.
403 { error, code? } Con code: "LOCATION_NOT_ALLOWED" tu clave no puede operar con esa subcuenta (alcance limitado por el administrador). Con code: "CHARGES_DISABLED" el administrador ha cortado los cobros de tu app: deja de cobrar y sigue sirviendo o para, según tu producto (el resto de la API sigue funcionando). Ramifica por code, no por el texto.
404 { error } Tarifa inexistente o inactiva, o subcuenta no conectada.
El error que cuesta dinero: tratar todo lo que no sea 201 como fallo y volver a cobrar con un event_id nuevo. Acepta 200 y 201 como éxito, y reintenta siempre con el mismo identificador.

04 Las 7 reglas de oro

Se mueve dinero real de tus clientes. Estas siete reglas son todo lo que hay que respetar.

  1. Un event_id único y estable por operación

    Derívalo de tus propios identificadores, nunca de un aleatorio ni de la hora: hermes-conv842-lote7, vslboost-video91-transcode, emails-envio-55231. Es lo único que impide cobrar dos veces.

  2. Ante fallo transitorio, reintenta con el mismo event_id

    Timeout, error de red, 502, 503, 429: repite la misma petición. Generar un identificador nuevo «para desatascar» es exactamente lo que duplica el cobro. Incluye los cargos en unknown: el reconciliador solo los cierra si GoHighLevel confirma que cobró; si dice que no existe, no lo da por fallido (por diseño). Pasados ≥ 5 minutos, reenvía tú el mismo event_id: es seguro, el POST reconcilia primero y solo re-ejecuta si GHL confirma que el intento anterior no cobró.

  3. 200 idempotent es éxito, no fallo

    Significa que ese cobro ya estaba hecho. Trata 200 y 201 igual.

  4. 409 significa «espera», no «ha fallado»

    Hay un intento en vuelo para ese event_id. Reintenta con backoff: normalmente el anterior termina en segundos y recibes 200 idempotent. Si aquel proceso murió, el desbloqueo duro llega a los 90 segundos.

  5. No cambies el payload de un event_id ya enviado

    Un reintento reescribe la fila con lo que mandes, pero GoHighLevel sigue deduplicando por el intento original y acabará mandando el importe realmente cobrado. Si de verdad cambian las unidades, es otro hecho facturable: usa un event_id nuevo.

  6. No mandes price en tarifas fijas

    Devuelve 400. Consulta price_type en GET /api/v1/meters y envía price solo si es dynamic.

  7. Cobra después de entregar, o comprueba fondos antes

    Si cobras antes y tu proceso falla, tendrás que reembolsar. Si entregas primero, sabes exactamente qué cobro reintentar.

05 Código listo

Esta función implementa las seis reglas. Cópiala y adapta el transporte a tu stack.

javascript
const BASE = 'https://marketplace.escaladoacelerado.es'
const KEY  = process.env.MD_API_KEY

const sleep = (ms) => new Promise((r) => setTimeout(r, ms))

export async function cobrar({ locationId, meter, units, eventId, price, description }) {
  const body = { location_id: locationId, meter, units, event_id: eventId, price, description }

  for (let intento = 0; intento < 5; intento++) {
    let res, data
    try {
      res = await fetch(`${BASE}/api/v1/charges`, {
        method: 'POST',
        headers: { Authorization: `Bearer ${KEY}`, 'Content-Type': 'application/json' },
        body: JSON.stringify(body),
        signal: AbortSignal.timeout(35_000),
      })
      data = await res.json().catch(() => ({}))
    } catch {
      await sleep(2000 * (intento + 1)); continue      // red/timeout → MISMO event_id
    }

    // 200 (ya cobrado) y 201 (cobrado ahora) son ambos ÉXITO
    if (res.status === 201 || res.status === 200) return data.charge

    // transitorios: se repite la MISMA petición
    if ([409, 429, 502, 503].includes(res.status)) {
      await sleep(2000 * (intento + 1)); continue
    }

    // 400/401/403/404: error de tu petición, no insistas
    throw new Error(`Cobro rechazado (${res.status}): ${data.error}`)
  }

  // Sin confirmar tras los reintentos: NO cobres con otro event_id.
  // El reconciliador lo cierra solo; compruébalo luego con
  // GET /api/v1/charges?event_id=...
  throw new Error('Cobro sin confirmar; se reconciliará automáticamente')
}
¿Y si tras los 5 intentos sigue sin confirmarse? No pasa nada: no vuelvas a cobrar. Un proceso en segundo plano revisa cada 60 s los cobros sin confirmar, le pregunta a GoHighLevel y los cierra correctamente. Consulta el estado final con GET /api/v1/charges?event_id=….

06 Resto de endpoints

Todos con la misma cabecera de autenticación. Tu clave solo ve y toca datos de tu propia app.

GET /api/v1/locations/:locationId/has-funds ¿Puede pagar esta subcuenta?
GET /api/v1/access/:locationId ¿Tiene suscripción vigente a tu app?
GET /api/v1/charges Historial de tus cobros
DELETE /api/v1/charges/:id Reembolsar un cobro tuyo
GET /api/v1/meters Tarifas activas y sus precios
GET /api/v1/locations Subcuentas que puedes cobrar

Comprobar fondos

GET /api/v1/locations/:locationId/has-funds
{ "hasFunds": true, "credit": 12.5, "wallet_has_funds": null }

credit es el saldo interno del cliente, que se gasta antes que su wallet. Si hay crédito, hasFunds ya es true sin preguntar a GoHighLevel y wallet_has_funds viene a null. Errores: 404 no conectada, 409 conexión caída, 502 GHL no respondió.

No reserva nada: el saldo lo comparten todas las apps del marketplace, así que entre tu comprobación y tu cobro otro puede haberlo consumido. Es un semáforo previo, no una garantía.

Si vendes por suscripción, no cobras tú

Hay dos formas de cobrar y puedes usar las dos a la vez:

Cobro por usoCobro por suscripción
Quién cobra Tu app, con POST /api/v1/charges El marketplace, solo, cada periodo
Cuándo Cada vez que el cliente consume Cada N meses, en la fecha de renovación
Qué implementas La llamada de cobro Nada: solo GET /api/v1/access/:locationId

Si tu app es de plan mensual (o anual), no implementes cobros: el administrador crea la suscripción con su precio y renovación automática, el marketplace la cobra del saldo del cliente y le extiende el acceso solo. Tu app únicamente pregunta si hay acceso y sirve o corta.

Qué pasa cuando no se puede cobrar la renovación (sin saldo, subcuenta desconectada…):

  1. La renovación se intenta hasta 1 hora antes de que venza el periodo: si va bien, el acceso se extiende antes de caducar y nunca ves un access: false entre el vencimiento y el cobro.
  2. Si falla, la suscripción entra en gracia (3 días por defecto; lo fija el administrador): access sigue siendo true, pero llega "grace": true y ends_at pasa a ser el fin de la gracia. Es el momento de avisar al cliente («recarga tu saldo»). El marketplace reintenta cada 24 h.
  3. Agotada la gracia, access pasa a false con "reason": "expired". Si un reintento posterior cobra, el acceso vuelve solo. Agotados los reintentos (10 días por defecto), queda impagada: "reason": "past_due" hasta que el administrador la reactive.

Las pruebas gratuitas (trial) que no consiguen convertirse en pago no tienen gracia: se cortan al vencer.

Control de acceso, si vendes por suscripción

GET /api/v1/access/:locationId
{ "access": true, "via": "app", "plan": "Emails Disruptivo · Pro",
  "status": "active", "grace": false,
  "starts_at": "…", "ends_at": "2026-11-07T12:00:00.000Z",
  "subscription_id": 15, "credit": 12.5 }

// sin acceso:
{ "access": false, "reason": "past_due", "credit": 0 }

El administrador concede o corta el acceso desde su panel y tu app se entera sola: no tienes que tocar código para dar una prueba gratis o cortar a quien no paga.

CampoQué es
viaCómo llega el acceso: app (suscripción directa a tu app) o plan (un pack que la incluye).
planNombre del plan, si lo tiene (null p. ej. en una prueba sin plan). Muéstralo tal cual.
statustrial, active o comped (cortesía).
gracetrue = renovación impagada en reintento: el cliente sigue dentro, avísale. Lo normal es false.
ends_atFin del acceso vigente (null = sin caducidad). En gracia, es el fin de la gracia.
reasonSolo sin acceso: past_due (impagada), expired (caducó o agotó la gracia), canceled, scheduled (empieza más adelante) o none (nunca tuvo suscripción).

Ramifica por access/grace/reason, nunca por textos.

Filtrar por event_id es la forma de saber cómo acabó un cobro que quedó dudoso.

07 Modo prueba

Para integrar sin gastar un céntimo.

El administrador puede activarlo a tres niveles: global, por subcuenta o por app. Con cualquiera activo, tus cobros se registran con status: "test" y la respuesta trae test_mode: true, pero no tocan el wallet ni el crédito.

Pídele al administrador que active el modo prueba de tu app mientras integras, y que lo desactive el día que pasas a producción. Haz entonces un cobro real pequeño y compruébalo con él en el panel.

08 Límites y operativa

Lo que conviene saber antes de que pase en producción.

TemaComportamiento
Rate limit 600 peticiones/min por API key. Todas las respuestas traen X-RateLimit-Remaining; al pasarte, 429.
Aislamiento Con tu clave solo ves tus cobros. Un DELETE sobre el cargo de otra app devuelve 404.
Alcance El administrador puede limitar tu clave a subcuentas concretas. Fuera de esa lista recibes 403 con code: "LOCATION_NOT_ALLOWED" (en POST /charges, /has-funds y /access), y GET /api/v1/locations solo lista las permitidas. Por defecto la clave alcanza a todas.
Reconciliación Cada 60 s se revisan los cobros unknown (>3 min) y los pending huérfanos (>10 min): se consulta a GoHighLevel y se cierran correctamente. Ningún cobro sin confirmar se pierde ni se duplica.
Rotación de claves Si la clave se filtra, el administrador la regenera y la anterior deja de funcionar al instante. Guárdala en una variable de entorno, nunca en el repositorio.
